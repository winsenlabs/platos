### 1.6 Reproducibility of the shipped artifact

- `apps/agent/Dockerfile:36` and `apps/webapp/Dockerfile.platos:46,57` install with `--no-frozen-lockfile`. Only `internal-packages/tenancy-database/Dockerfile.migrations:12` is frozen.
  *Precisely:* `--no-frozen-lockfile` does **not** force re-resolution of ranges the lockfile already satisfies — the falsification pass overstates this. What it does is remove the failure mode: any divergence between manifest and lockfile is silently resolved fresh against the registry at build time instead of failing the build. Given that `turbo prune --docker` (`Dockerfile.platos:10`) **rewrites the lockfile** and `apps/webapp/scripts/restore-patches.cjs` (`:38`) **rewrites root `package.json`** mid-build, divergence is manufactured on every webapp build. The image is not reproducible by construction.
- `apps/agent/Dockerfile:34`: `RUN sed -i '/docs/d' pnpm-workspace.yaml` — a substring delete on the workspace manifest during the build.
- Registry fetches outside `pnpm-lock.yaml`: `npx -q turbo@2.5.4` (`Dockerfile.platos:10`), `pnpx prisma@6.14.0 generate` (`:49`), `go install github.com/pressly/goose/v3/cmd/goose@v3.26.0` (`:3`, and `Dockerfile.migrations:3`). Node base images are digest-pinned (good); apt packages are unversioned.
- **Historical observation — closed by WIN-253:** `internal-packages/clickhouse/Dockerfile:1,4` used `FROM golang` (untagged, no digest) plus `go install …/goose@latest`. The approved split deleted this unreachable package Dockerfile; it is no longer a pinning task or a shipping build input. The retained migration images continue to own the live Goose/schema path.
- **`goose` is a runtime dependency, not a build tool.** `apps/webapp/scripts/entrypoint.sh:25-26` sets `GOOSE_MIGRATION_DIR=/platos/internal-packages/clickhouse/schema` and runs `/usr/local/bin/goose up` on every container start. A Go module tree governed by no lockfile in this repo.

### 5.2 Proposed grouping / gating policy

**Grouped by ecosystem, one PR per group** — these packages have cross-package invariants and cannot be bumped individually:

| group | members | cadence |
|---|---|---|
| `ai-sdk` | `ai`, `@ai-sdk/{anthropic,google,google-vertex,openai,provider,provider-utils,gateway,openai-compatible}` | weekly, minors+patches |
| `chat` | `chat`, `@chat-adapter/{discord,slack,telegram,whatsapp,state-pg,shared}` | weekly |
| `trigger` | `@trigger.dev/{sdk,core,platform,companyicons}` | weekly, sdk+core lockstep-asserted |
| `mcp` | `@modelcontextprotocol/sdk`, `@cfworker/json-schema` | fortnightly |
| `nestjs` | `@nestjs/*`, `express`, `multer`, `cors` (declare these three) | fortnightly |
| `prisma` | `@prisma/{client,engines,instrumentation,config}`, `prisma`, **and the `pnpx prisma@X` literal in `Dockerfile.platos:49`** | monthly |
| `otel` | all `@opentelemetry/*` **plus `@sentry/{node,remix,opentelemetry,core,cli}`** — Sentry pins the OTel 1.x line, so they are one group whether or not you want them to be | monthly |
| `aws-sdk` | all `@aws-sdk/*` | monthly, auto-merge on green |
| `security` | anything with an advisory, any group, any time | immediate, bypasses cadence not gates |

**Gates every group PR must clear, in order:**
1. **Lockfile-controlled.** The PR body is a diff of `pnpm-lock.yaml` resolved versions, not of range strings. A range change with no resolution change is not an upgrade; a resolution change with no range change (the `lodash.omit` 4.5.0→4.18.0 case) **is** and must open a PR.
2. **Changelog-linked.** Every version step carries a link to the upstream release notes. Any package where notes cannot be found (`agentcrumbs`, `@jsonhero/*`, `intl-parse-accept-language`, `tailwindcss-textshadow`) is refused automatic promotion and routed to manual review — that inability is itself the signal.
3. **Test-gated by the ecosystem's contract test** from §2. A group has no gate until its contract test exists; groups without one are frozen at current pins, not auto-updated. Contract tests must run with **`--frozen-lockfile` and install scripts enabled**, matching the image, because CI's `--ignore-scripts` currently never exercises the 7 postinstalls that run in production.
4. **Staged through immutable candidates.** Promote by **image digest**, not by tag or by re-running `pnpm install`. This historical recommendation required the remaining app-image reproducibility fixes. **WIN-253 closed its ClickHouse sub-item by deleting the unreachable `internal-packages/clickhouse/Dockerfile`; the live Goose/schema path remains in the retained, separately governed migration images.** Do not recreate or pin the deleted package Dockerfile.
5. **Majors behind an explicit migration issue.** No major crosses without a linked issue that names the breaking changes, the migration steps, and the rollback. Standing majors today, each needing one: **NestJS 11→12** (6 packages + an undeclared Express major moving underneath), **Prisma 6→7** (four locations, one of them a Dockerfile), **Sentry 8/9→10** (prerequisite for OTel; a patch must be rebased), **OTel 0.203→0.221 / core 2.x** (blocked on Sentry), **React 18→19**, **zod 3→4** (already partially in the tree), **Express 4→5** (already partially in the tree).
6. **Patched packages are their own gate.** Any bump to a package still present in `pnpm.patchedDependencies` must rebase its patch in the same PR. WIN-253 removed the unreachable `@upstash/ratelimit` and `@window-splitter/state` packages and their tracked patches.
7. **New-transitive review.** Any group PR that introduces a package name not previously in the closure requires human sign-off. This is the gate that would have caught `@fingerprintjs/fingerprintjs-pro` (commercial licence + install script, arriving under an unused `0.1.x` React SDK) and `breakword` (GPL-2.0 under release tooling).
8. **SBOM + licence diff on every PR.** Generate CycloneDX from the *closure*, not the manifests, per image; fail on any new non-permissive licence, any `no license field`, and any non-SPDX string. The 14%-coverage gap is exactly why the GPL-2.0 hit survived a full manual audit.

**Preconditions before any of this is worth automating** (all cheap, all removals):
- Delete the 126 repo-wide orphan runtime deps from `apps/webapp/package.json`. That is 126 packages of attack surface, licence obligation and upgrade noise removed by editing one file — and it takes `@fingerprintjs`, `posthog-js`, `@vercel/sdk`, `class-variance-authority`, `dompurify`, `cuid`, `react-window-splitter` (+ its patch), `@upstash/ratelimit` (+ its patch) and `@depot/cli` with it.
- Move `@changesets/cli`, `@remix-run/changelog-github` from root `dependencies` to `devDependencies` (removes the GPL-2.0 path and two CLIs from the runner).
- Declare `express`, `multer`, `cors` in `apps/agent/package.json`; declare `@prisma/client` where it is used.
- Fix `NOTICE` to match `LICENSE` and record the `dompurify` MPL/Apache election.
