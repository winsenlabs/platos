# WIN-293 — Operator authentication boundary (M0.8)

Status at `tejas/m0-completion` (base `v1` `fb28444`): **in-repo acceptance
implemented and tested; one clause (full cryptographic workload identity) is an
honest operator/infra residual.**

## What changed (apps/agent/src/auth/scope.guard.ts)

The direct-header path used to stamp `principal: "operator"` from `!viaProxy` +
scope-header presence *before* any credential check, then confirm or reject. The
zero-key fail-open was already closed (WIN-296) and is preserved. This change
closes the remaining acceptance:

- **Principal only after auth (clause 5).** The scope is now built **without** a
  principal. `"operator"` is assigned **only** inside the positive-credential
  branches: a valid internal control-plane token, a positive Environment
  AccessKey, or a valid one-use bootstrap. A fail-closed reject can no longer
  leave an operator principal on the request. Regression-guarded by the corrected
  WIN-296 lifecycle-reject assertion (`principal` `.not.toBe("operator")`).
- **Network placement is not an authorization (clause 3).** `!viaProxy` is demoted
  to explicitly non-authorizing perimeter defense. The operator grant rests solely
  on a positive cryptographic credential. Proven by a test where a **proxied**
  request carrying a valid-looking internal token is still rejected and
  `verifyAccessKey` is never consulted.
- **Reason-coded, redacted telemetry (clause 6).** `AuthDecisionReason` (a stable
  enum) + `emitAuthDecision()` emit exactly one event per accept/reject:
  `ACCEPT_CONTROL_PLANE_TOKEN`, `ACCEPT_ACCESS_KEY`, `ACCEPT_BOOTSTRAP`,
  `ACCEPT_HARNESS_NO_AUTHSERVICE`, `ACCEPT_SESSION_TOKEN`, `REJECT_NO_CREDENTIAL`,
  `REJECT_INVALID_KEY`, `REJECT_CONTROL_PLANE_REQUIRED`, `REJECT_INVALID_AGENT_SCOPE`,
  `REJECT_AGENT_SCOPE_MISMATCH`, `REJECT_PROXIED_RAW_HEADERS`, `REJECT_MISSING_CREDENTIALS`.
  Coverage spans BOTH the direct-header path and Path 1 (session-token) accepts and
  rejects plus the internal-token bypass accepts. Events carry only
  non-secret scope ids, route, principal, and trace/correlation ids — a redaction
  test proves no token/key material is ever logged. Rejects log at `warn` so they
  are independently alertable.
- **Negative-control matrix (clause 7).** New tests cover: no configured key
  (`REJECT_NO_CREDENTIAL`), configured-but-wrong/revoked/retiring key
  (`REJECT_INVALID_KEY`), spoofed `X-Forwarded-For` (`REJECT_PROXIED_RAW_HEADERS`),
  and internal-token rotation (old token rejected, current token accepted) — each
  asserting the request never becomes operator.
- **Operator-operation enumeration (clause 2).** `docs/audits/M0.8-operator-operations.md`
  (generated by `scripts/operator-operations.mjs`) lists all **120**
  operator-protected operations; the count is cross-checked from a second
  mechanism by `scripts/rest-census-independent.mjs` (manifest operator ≥ the
  independent `requireOperator` floor), so it cannot silently under-report.

All 149 auth tests pass (`scope.guard.test.ts`, `auth.service.access-key-bootstrap.test.ts`,
`env-internal-auth-sentinel.test.ts`); 0 tsc errors in changed files.

## Residual — cryptographic workload identity (clause 4)

The trusted service-to-service credential (`PLATOS_INTERNAL_AUTH_TOKEN`) is a
**shared secret**, verified in constant time (`crypto.timingSafeEqual`) and now
the **sole** basis for S2S operator trust (network placement grants nothing).
This is a bearer credential, not full **workload identity**. Genuine workload
identity — mutual TLS with per-service certificates, or short-lived signed
(SPIFFE/JWT) assertions — requires certificate/secret distribution and a
coordinated deploy across the webapp and agent, which is an **operator/infra**
change outside this repository. It is recorded here as a residual risk and a
follow-up, not silently claimed as done.

### Operator-boundary follow-ups (host, not repo)
- Provision/rotate the real `PLATOS_INTERNAL_AUTH_TOKEN` on the host through the
  authorized deploy procedure (≥32 random bytes; equal on agent and webapp).
- Add a deploy preflight that verifies token presence + agent/webapp equality
  without printing its value.
- Document rotation ordering (dual-token grace or coordinated restart), rollback,
  and worker propagation.
- Keep agent `:3100` / webapp `:3030` loopback-bound as defense-in-depth.
