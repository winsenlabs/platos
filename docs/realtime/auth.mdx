Realtime requests must use a token issued for the specific resource being accessed. Platos does not expose an SDK method for minting arbitrary public JWT claims.

## Run-scoped tokens

Trigger tasks from trusted backend code. The returned handle includes a short-lived `publicAccessToken` scoped to that run:

```ts
import { tasks } from "@trigger.dev/sdk";

const handle = await tasks.trigger("my-task", { message: "Hello" });

return {
  runId: handle.id,
  publicAccessToken: handle.publicAccessToken,
};
```

Pass only the run ID and token to the client. The client can then subscribe to that run:

```tsx
import { useRealtimeRun } from "@trigger.dev/react-hooks";

export function TaskStatus({
  runId,
  publicAccessToken,
}: {
  runId: string;
  publicAccessToken: string;
}) {
  const { run, error } = useRealtimeRun(runId, {
    accessToken: publicAccessToken,
  });

  if (error) return <p>{error.message}</p>;
  return <p>{run?.status ?? "Loading"}</p>;
}
```

The token is generated as part of the authenticated trigger response. Do not construct it in browser code, expose a project secret key, or rely on the removed public-claims endpoint.

## Waitpoint tokens

`wait.createToken()` returns a `publicAccessToken` scoped to that waitpoint. Use that token only for the corresponding client-side waitpoint operation. See [Wait for token](/wait-for-token).

## Frontend triggering

Platos does not publish a general-purpose frontend trigger-token minting API. Trigger tasks through an authenticated Platos backend endpoint, then return only the run-scoped handle fields the client needs for Realtime subscriptions.
