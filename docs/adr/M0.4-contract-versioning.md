## 1. Versioning model — one principle, six expressions

### 1.1 The unifying principle

**A version is a property of the *contract*, not of the *code path*.** Every transport pins exactly one **MAJOR** axis — the only place a break is ever allowed — and stamps one **additive build id** derived from a single canonical manifest. Every reader is required to **ignore unknown fields, unknown event types, and unknown enum members on open-enum fields**. Unknown-tolerance + additive-only changes = *no consumer can break inside a major*. A break is never silent: it is a new major mounted **alongside** the old one, with an explicit, machine-readable deprecation window on what it replaces.

Three consequences make this enforceable rather than aspirational:

1. **The version is generated, never hand-written.** It is read out of `operation-manifest.generated.json` and stamped onto the wire; a hand-edit that disagrees with the manifest fails CI.
2. **The break axis is structural, not a string.** REST major = URL segment via Nest `@Version`, not a per-controller literal; MCP major = `serverInfo.version` MAJOR from one const; stream major = a monotonic int per envelope family. A drift-check reads the *structure*, so two code paths cannot privately disagree on the version.
3. **In-flight state outlives the version.** Durable tokens, idempotency keys, and Trigger task-ids are **frozen across all majors** so a 1-hour HITL approval minted pre-upgrade still resolves post-upgrade.

### 1.2 What "V1" means precisely

**V1 is the frozen *semantic surface*, not a URL.** Concretely:

| Transport | V1 major is expressed as | V1 freezes |
|---|---|---|
| REST | URL prefix `/api/v1` (promoted from 18 per-controller literals to `setGlobalPrefix("api")` + <code>enableVersioning(&lbrace;URI, defaultVersion:"1"&rbrace;)</code> + `@Version("1")`) | 417 capabilities (300 agent bindings + 117 BFF), stable `error.code` strings, envelope shape, auth class, pagination semantics |
| MCP | `serverInfo.version` **MAJOR = 1** across all 3 servers, from one `PLATOS_MCP_CONTRACT` const | 202 tool names + input schemas, `requiresAdminTier`, OAuth scope-set <code>&lbrace;mcp:read, mcp:write, mcp:tools&rbrace;</code>, RPC error codes |
| WS / SSE | `sv = 1` **per envelope family** (`ws.agent_event`, `sse.turn`, `webhook.ingest`, `internal.callback`, `trigger.payload`) | each event `t`, approval/durableToken shape, per-lane usage block, replay semantics |
| Workflow | `pv = 1` in body + `X-Platos-Payload-Version` header, mirrored to `metadata.pv` | 18 Trigger task payloads + 1 Session; decoded at *enqueued* pv (survives the M3.3 provider swap) |

**One build id ties them together.** `manifestVersion` (this milestone = **M0.4**) is the single additive build stamp: emitted in OpenAPI `info.version`, in the REST response header `X-Platos-Contract-Version: M0.4`, in MCP `serverInfo._meta["platos.dev/contract"].catalogDigest`, and in the stream contract snapshot. It is **advisory** — clients pin the MAJOR (URL / serverInfo / sv / pv); the build id only lets a client *assert a floor* (`X-Platos-Contract-Min` → `400 CONTRACT_TOO_OLD`; MCP `params._meta["platos.dev/minContract"]` → `-32600`). Because all six axes are derived from *one* manifest, a single screen consuming REST + WS + MCP (e.g. `17-thread`, `19-playground`) never sees them skew.

### 1.3 The one wire rule, stated once

> **Additive is free and invisible; breaking is a new major mounted alongside, announced by `Deprecation`/`Sunset` (REST), <code>_meta.deprecated&lbrace;sunset,replacedBy&rbrace;</code> (MCP), or <code>server.deprecation&lbrace;code,removeAfter&rbrace;</code> (stream), with a ≥90-day window (≥180 days / ≥1 major for MCP tools).**

Additive-in-major: add routes/tools/events; add optional inputs; add response/`_meta` fields; add error codes; add enum values on open-enum fields; relax validation; deprecate-but-keep. Forces-major: remove/rename a field/route/tool/event; change a type; change an `error.code` / RPC code string; tighten validation or change a default; remove an enum value; change auth class, scope grant, pagination, HMAC base-string, or `seq`/replay semantics.

## 4. Compatibility & deprecation policy (the existing surface)

### 4.1 The load-bearing invariant: an alias cannot silently diverge

Every legacy/alias path is an **explicit generator row** — exactly like the existing `DEPRECATED_RULES` entry `legacy-platos-memory-prefix` (`/api/v1/platos/memory` → `/api/v1/memory`, all 15 routes classified `DEPRECATED`) and the MCP `toolNamePolicy.aliasesMustBeExplicit:true`. An alias **MUST**:

1. **appear in `operation-manifest.generated.json` with `classification:DEPRECATED` + non-null `replacement`/`supersededBy`** — never inferred;
2. **delegate 1:1 to the canonical handler — no independent implementation.** Fan-in is *enforced by a test asserting `aliasHandler === canonicalHandler`* (REST) / *same source file + same `schemaHash`* (MCP) / *byte-identical emitted contract* (stream `/agent`≡`/agent/:agentId`, `platos.agent.durable-turn`≡`platos.chat.session`);
3. **carry the deprecation signal on the wire** (below).

Any route/prefix **not** covered by an explicit policy rule classifies `REST_ONLY`; if it collides with or shadows a canonical route, **generation fails**. The 300 `/api/v1/agent/*` routes are pinned canonical v1; when a split route supersedes one, **the old route re-registers *as* an alias, never as a fork.**

### 4.2 How a consumer discovers a deprecation

| Transport | Live wire signal | Static/catalog signal |
|---|---|---|
| REST | `Deprecation: true` + `Sunset: <RFC-8594 date>` headers; retiring a *field* → `Warning: 299` + <code>meta.warnings:[&lbrace;code:"field_deprecated",field,sunset,supersededBy&rbrace;]</code> | OpenAPI `deprecated:true` + `x-platos-classification:DEPRECATED` + `x-platos-superseded-by` + `x-platos-sunset` |
| MCP | tool stays in `tools/list` (deprecated tools are **never hidden**, unlike admin-tier), flagged <code>_meta.deprecated&lbrace;sunset,replacedBy&rbrace;</code> | `platos://contract` resource + manifest `aliases[]` |
| Stream | <code>server.deprecation&lbrace;code,removeAfter&rbrace;</code> frame; `removeAfter` is **machine-readable and CI-enforced** | AsyncAPI generated snapshot |

### 4.3 Windows

- **REST route/field:** `Sunset ≥ 90 days` **AND** removal only in `/api/v2`. **An operation cannot vanish inside v1.**
- **MCP tool:** old name stays live, flagged, for **≥1 major / ≥180 days**; removal after sunset is a v2 event.
- **Stream `minSv` raise:** ≥90-day `removeAfter` window; two adjacent `sv` coexist (server advertises `[minSv,maxSv]`).
- **OAuth scope narrowing** (MCP): invisible to a client whose token still validates → **must** be a v2 event that bumps well-known `x-platos-contract` major.
- **Frozen across ALL versions** (in-flight state outlives upgrades): opaque `durableToken` + `/durable-approvals/:token/resolve`; idempotencyKey inputs; Trigger task-id namespace + HMAC / `X-Platos-Internal-Auth` callback contract. This is what preserves in-flight runs through the M3.3 DurableRuntime provider swap.

## 5. Generated-artifact governance — one source of truth

**Source of truth: `apps/agent/scripts/generate-control-plane.mjs`**, producing **`operation-manifest.generated.json`** as the canonical inventory. It AST-walks every mounted Nest controller + every MCP tool handler, applies the classification/alias policy, and deterministically emits **three artifacts**: the manifest, `openapi/openapi.generated.json`, and `docs/control-plane-parity.generated.md`. `--check` mode byte-compares committed vs regenerated and **exits 1 on any diff** ("generated artifact drift"). It is already wired into `prebuild`, `build:strict`, `typecheck`, and `check:control-plane`.

Two existing tests close the loop and are retained: `control-plane-contract.test.ts` (runtime MCP router's registered tools == manifest inventory: name syntax, admin-tier, schemas); `packages/platos-client` `generated-contracts.test.ts` (every SDK method exists as the same method+path in **both** OpenAPI **and** the manifest — the client cannot diverge).

**Extend for V1 versioning (the M4 governance delta):**

1. Assert `openapi.info.version == manifest.manifestVersion == served X-Platos-Contract-Version header`.
2. **No-bare-prefix lint** — every route resolves via `@Version("1")`/global-prefix; **fail on any literal `"api/v1"` string** (enforces contract-not-path).
3. **Alias fan-in** — every DEPRECATED/alias op has non-null replacement **and** resolves to the same `controller.handler` (REST) / same source+`schemaHash` (MCP) / byte-identical emitted contract (stream) as its canonical.
4. **Breaking-change guard** — diff committed OpenAPI vs `openapi.previous.json` (prior tag); any removed/retyped operation or field without a `/api/v2` bump fails. MCP: semver monotonicity on the manifest (vanished tool / new required input / narrowed enum without a matching `aliases[]` entry fails "breaking change requires v2").
5. **MCP digest** — persist per-tool `schemaHash=sha256(canonical(inputSchema))` + platform `catalogDigest`; assert `serverInfo.version MAJOR===PLATOS_MCP_CONTRACT MAJOR` across all 3 controllers; assert `scopes_supported===PLATFORM_MCP_SCOPES/ENTITY_MCP_SCOPES` consts. **Canonicalize (sorted keys)** so a benign reformat is not false drift.
6. **New `check:stream-contracts`** beside it — canonical source `stream-webhook-workflow.contracts.ts` (Zod/TypeBox per family × sv/pv); AST-walk all emit sites (`.emit(`, SSE `res.write`/`formatSSE`, `redis.publish(approval:event|thread:lifecycle|overview:event)`, Trigger `payload:`) → orphan-in-either-direction fails; regen AsyncAPI+JSON-Schema+TS client and byte-compare; assert OpenAPI streaming/webhook/internal responses `$ref` the same schemas; alias equality; every example validates at its sv **and** round-trips under the sv-1 reader ignoring unknowns.

**Known bug to fix before freeze:** the oracle **undercounts by 3** (manifest `x-platos-rest-operation-count=297` vs 300 real agent bindings; 417 total). The drift gate is what will surface it — but **the manifest must be reconciled to 300/417 and the MCP 202-tool baseline verified before `schemaHash`/`catalogDigest` are frozen as v1**, or the v1 digest bakes in the miscount. **This is a hard M4 pre-gate, not a follow-up.**

### Original proposal — decisions the founder had to make

**D0 — Screen-count reconciliation (blocker).** The charter says 47 settled screens; M0.3 demand data enumerates 43 (missing `06`, `33`, `43`, + one). Options: **(a)** treat 43 as authoritative and update the charter to 43; **(b)** obtain demand for the missing 4 before M4 exit. **Recommend (b)** — the acceptance criterion is "zero orphans"; four settled-but-undemanded screens are exactly the kind of silent gap this milestone exists to prevent. Cheap to close now, expensive to discover in M4.

**D1 — Where the REST version lives: URL path vs header vs both.** Options: **(a)** URL only (`/api/v1`); **(b)** header only (`X-Platos-API-Version`); **(c)** **both — URL pins the *major* (the only breaking axis), header carries the additive *build id*.** **Recommend (c).** URL-major matches how SDK/webapp/embed already construct paths (`agentRequest()`, `packages/platos-client` <code>&lbrace;baseUrl&rbrace;+path</code>, `/api/v1/public/*`) and lets v2 mount alongside; the header build id lets a client assert a floor without churning URLs. **Non-negotiable rider:** migrate the 18 hardcoded `@Controller("api/v1/...")` literals to `setGlobalPrefix`+`@Version("1")` **first**, or the "version is a contract, not a path" guarantee is unenforced (the drift-check only reads a string today).

**D2 — Does MCP carry a Platos version beyond the protocol version?** Options: **(a)** no — rely only on wire `protocolVersion "2025-06-18"`; **(b)** yes — a Platos contract semver orthogonal to the protocol. **Recommend (b), strictly orthogonal.** The MCP protocol date is spec-negotiated and carries no Platos semantics; conflating them breaks handshake negotiation. Platos version rides in `serverInfo.version` (valid semver, MAJOR=1) + `_meta["platos.dev/contract"]` (the spec-sanctioned extension channel, so strict clients that reject unknown top-level keys still handshake) + a `platos://contract` resource. This is what lets a tool rename/deprecation be visible and drift-checked without touching MCP clients. **Prerequisite:** collapse the `"0.1.0"` hardcoded in `mcp-router.ts:249`, `mcp-entity.controller.ts:910`, `docs-mcp.controller.ts:268` into one `PLATOS_MCP_CONTRACT` const.

**D3 — How long is the v1 compatibility window for existing clients?** Options: **(a)** 90 days; **(b)** 180 days; **(c)** tiered — REST/stream 90 days, MCP tools 180 days, in-flight durable state frozen indefinitely. **Recommend (c).** REST/stream consumers are first-party (webapp, SDK) and can move on 90 days; MCP tools are consumed by *third-party* agent clients that pin tool names and deserve ≥180 days / ≥1 major; durable tokens and Trigger task-ids must be frozen **forever** (a 1h+ HITL approval minted pre-upgrade must resolve post-upgrade, across the M3.3 provider swap). Encode all three as machine-readable `Sunset`/`removeAfter`, CI-enforced.

**D4 — Baseline default for absent stream version.** Options: **(a)** reject frames lacking `sv`/`pv`; **(b)** **treat absent `sv`/`pv` as `1`.** **Recommend (b).** Introducing `sv` *is* the sv=1 baseline; today no frame carries a version field, so any reader that rejects absent-`sv` breaks against every current frame. Negotiation must default missing→1, never reject. (Same for the idemKey fix: compute over a version-stable subset `threadId+clientMessageId`, not the full payload, so a version-straddling retry doesn't duplicate a turn.)

**D5 — How to introduce the canonical envelope over live bare-object routes.** Retrofitting <code>&lbrace;data&rbrace;</code>/<code>&lbrace;error:&lbrace;...&rbrace;&rbrace;</code> onto routes that return bare objects (erasure receipt, <code>&lbrace;error:"IDEMPOTENCY_KEY_CONFLICT"&rbrace;</code>) is itself breaking. Options: **(a)** ship envelopes only on new v1 contexts, leave existing routes bare (two shapes forever — rejected, defeats the point); **(b)** **dual-emit compat shim** — existing routes emit both shapes during the v1 window, new/`Accept`-negotiated clients get the envelope, bare shape deprecated with `Sunset`; **(c)** force `/api/v2` for the envelope. **Recommend (b)** for the ~existing surface and **envelope-native from day one** for all new M4 contexts (clusters C/D/E). This avoids a premature v2 while making the envelope the single forward shape.

**D6 — Self-host the version-explorer / OpenAPI UI.** Today Swagger UI + `swagger-ui-dist` load from the unpkg **CDN** (external), so the canonical version doc is neither offline nor self-contained and couples to a third party. Options: **(a)** keep CDN; **(b)** vendor `swagger-ui-dist` locally. **Recommend (b)** — the artifact that *documents* the contract should not depend on a CDN's availability, especially for self-hosted installs.

**D7 — Field-level compat enforcement (schema declaration).** OpenAPI today "intentionally does not invent request/response schemas until a source schema is available," so only method/path/classification are drift-checked — **the envelope, cursor pagination, and field-level deprecation cannot be verified at field granularity.** Options: **(a)** accept method/path-level enforcement only; **(b)** **mandate DTO schema declaration on all new v1 contexts + the retrofitted envelope, backfilled on existing routes over the window.** **Recommend (b)** — without declared DTOs, "additive-only field compat" is a policy nobody can enforce; the new contexts (which are the bulk of M4) should be born with schemas so the breaking-change guard actually guards fields.
